# Purpose of the demo

The demo shows how a team can connect AWS, Azure, and GCP into one private network, then use an AI coding agent to extend it safely. It represents a common real-world situation: a client ends up spread across several clouds, whether on purpose (each cloud's strongest services, such as Bedrock, Azure AI Foundry, or Vertex AI) or by accident (acquisitions, different teams, separate project choices). The AWS Transit Gateway acts as the hub, with VPN tunnels out to Azure and GCP, so workloads in any cloud can reach workloads in the others over private addresses, and the VMs pinging each other across all three clouds are the proof of that. The live moment, where an AI agent adds a new AWS spoke to the hub from a plain-language request, mirrors how consulting teams now work: you describe what you want in a tool-agnostic prompt, the agent drafts the infrastructure code, and a human reviews the plan before anything is applied. The point is that the agent speeds up the work but doesn't replace judgment, so the skills you teach are the review questions, such as whether CIDR ranges overlap, whether routes exist in both directions, what it costs, and who owns teardown. A consultant can reuse the pattern directly with a client: a hub-and-spoke network to link separately run environments, an AGENTS.md-style context file to keep AI tools inside guardrails, and a review checklist to keep their output safe. This is lab scale, with small instances and static test routes, so a production version would add things like redundant and larger-capacity links, inspection and security controls, central logging, and a landing-zone structure for accounts and identity.
