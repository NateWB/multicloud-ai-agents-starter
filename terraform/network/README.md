# Multicloud network: AWS Transit Gateway <-> Azure + GCP

One root module, three providers, one state. Terraform orders everything automatically
(Azure public IP + GCP HA VPN gateway -> AWS customer gateways + VPNs -> Azure/GCP tunnels).

```
            Azure VNet 10.20.0.0/16          GCP VPC 10.30.0.0/20
                  | static (1 tunnel)              | BGP (4 tunnels, 2 AWS VPNs)
                  +-----------> AWS Transit Gateway <-----------+
                                       |
                                AWS VPC 10.10.0.0/16
```

## Before you apply
1. Use a **sandbox member account**, not the org management account.
2. Logins: `aws sso login --profile <p>`, `az login`, `gcloud auth application-default login`.
3. GCP: enable the Compute Engine API in the project. Azure: Microsoft.Network provider registered.
4. `cp example.tfvars terraform.tfvars` and fill in profile, subscription, project.
5. Check the CIDRs (10.10/16, 10.20/16, 10.30.0.0/20) don't overlap anything in the sandbox.

## Apply
```
terraform init
terraform validate
terraform plan -out tfplan
terraform apply tfplan        # Azure VPN gateway alone takes ~30-45 min
python3 ../../scripts/vpn_status.py --resource-group careerexp26-rg
```
Azure uses tunnel 1 only, so tunnel 2 of that AWS VPN connection shows DOWN. That is expected.

## Cost (rough; check current pricing) - destroy right after the event
Hourly charges: 3 AWS VPN connections, 4 TGW attachments (VPC + 3 VPN), Azure VpnGw1AZ,
4 GCP HA VPN tunnels. Low tens of dollars per day; hundreds if left up a month.

## Secrets
Pre-shared keys are generated by AWS and live in `terraform.tfstate`. State is git-ignored.
Never run `terraform show` or `terraform output -json` on screen.

## Teardown
`terraform destroy`, then see ../../scripts/teardown_checklist.md.
